# D&D 5e Full Character Implementation Plan

## Overview

The codebase has a solid foundation: data import pipeline, compendium browser, character creator wizard, and character sheet panel. However, creating a **fully rules-complete D&D 5e character** requires several missing features. This plan addresses all gaps in priority order.

---

## Phase 1: Critical Core Features (Must-Have)

### 1.1 Subclass Selection Step

**Problem**: No subclass selection. Classes have `system.subclass[]` arrays with full data (name, shortName, classFeature arrays), but the wizard never presents them.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx` — Add subclass step + logic
- `client/src/components/CharacterCreatorWizard.css` — Add subclass card styles

**Implementation**:
1. Add `'subclass'` to the `WizardStep` type and `STEPS` array, positioned after `'class'`
2. Make the subclass step **conditional** — only show if:
   - A class is selected AND
   - The class has `system.subclass` array with entries AND
   - The selected level >= 3 (or level >= subclass's `level` field)
3. On the subclass step:
   - Filter `characterData.class.system.subclass` to show only subclasses available at the character's level
   - Display subclass cards with name, description preview
   - On selection, store `characterData.subclass` (full subclass object)
4. In `createCharacter()`:
   - Merge subclass features into the feature pipeline alongside class features
   - The `collectEntityFeatures()` function already checks `system.subclass[].classFeature` and `system.subclass[].features` — just need to pass the subclass entity
   - Store `subclassData` on the character sheet (parallel to `classData`)
5. Update the `CharacterSheet` interface to include `subclass?: string` and `subclassData?: {...}`
6. Update the server route `POST /sessions/:sessionId/characters` to accept `subclass` and `subclassData`
7. Update the CharacterSheetPanel to display subclass name alongside class name

**Data flow**:
```
class.system.subclass[] → User picks one → subclass stored → collectEntityFeatures(subclass, 'subclass') → features merged → character.features[]
```

### 1.2 Skill Proficiency Selection

**Problem**: Class skill proficiencies (e.g., "Choose 4 from Acrobatics, Athletics, ...") are parsed from `classSystem.startingProficiencies.skills` but never presented as interactive choices.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx` — Add skill picker step + logic
- `client/src/components/CharacterCreatorWizard.css` — Add skill picker styles

**Implementation**:
1. Add `'skills'` to `WizardStep` and `STEPS`, positioned after `'subclass'` (or after `'class'` if no subclass)
2. Parse the skill choice data from `classSystem.startingProficiencies.skills`:
   - Handle string format: `"choose 4 from Acrobatics, Athletics, ..."`
   - Handle object format: `{ choose: { count: 4, from: [...] } }`
   - Extract available skill list and required count
3. Create a skill picker UI:
   - Checkbox grid of all 18 D&D 5e skills
   - Highlight which are from the class list
   - Show counter: "3/4 selected"
   - Include background-granted skills (pre-checked, disabled)
4. Store selections in `characterData.skillProficiencies: string[]`
5. In `createCharacter()`, merge into `characterSheet.skills`
6. The CharacterSheetPanel already displays `character.skills` — no change needed there

**Skill list** (D&D 5e standard):
```
Acrobatics, Animal Handling, Arcana, Athletics, Deception, History,
Insight, Intimidation, Investigation, Medicine, Nature, Perception,
Performance, Persuasion, Religion, Sleight of Hand, Stealth, Survival
```

### 1.3 Racial Ability Score Bonuses

**Problem**: Race ability bonuses are displayed as hints but never applied to the character's scores.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx` — Auto-apply bonuses

**Implementation**:
1. When race is selected, parse `raceSystem.abilityBonuses` or `raceSystem.abilityScores`:
   - 2014 format: `{ str: 2, dex: 1 }` or `"+2 Strength, +1 Dexterity"`
   - 2024 format: `"+2 to one ability, +1 to a different ability"` (custom origin)
   - Array format: `[{ str: 2 }, { dex: 1 }]`
2. Store the bonuses in `characterData.racialBonuses: Record<string, number>`
3. On the Abilities step, show two values per ability: base score and modified score (base + racial bonus)
4. In `createCharacter()`, use the **modified** scores for the character sheet
5. Display racial bonuses in the Review step

### 1.4 Speed from Race

**Problem**: Speed is hardcoded to 30.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx` — Read race speed

**Implementation**:
1. In `createCharacter()`, read `raceSystem.speed`
2. Parse it: could be number `30`, string `"30"`, or object `{ walk: 30, fly: 60 }`
3. Use the walk/ground speed as `characterSheet.speed`
4. Store full speed object in `templateInstance.stats.speed` for reference

### 1.5 Spell Selection for Spellcasting Classes

**Problem**: No spell picking during character creation. Only auto-collected from `classSystem.spells[]` which is typically empty.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx` — Add spell selection step
- `client/src/components/CharacterCreatorWizard.css` — Add spell selection styles

**Implementation**:
1. Add `'spells'` to `WizardStep` and `STEPS`, positioned after `'skills'`
2. Make the step **conditional** — only show if class has `spellcastingAbility`
3. Determine spell selection rules:
   - **Cantrips known**: from `classSystem.cantripProgression[level - 1]`
   - **Spells known/prepared**: varies by class (Wizard = Intelligence mod + level, Sorcerer = Charisma mod + level, etc.)
   - **Spell levels available**: based on character level (cantrips only at level 1, 1st-level spells at level 1 for full casters)
4. Spell picker UI:
   - Search bar to filter spells
   - Filter by spell level (cantrips, 1st, 2nd, etc. based on what's available)
   - Show known spell count: "3/6 spells known"
   - Click to add/remove from known list
5. Store in `characterData.knownSpells: any[]` (full spell objects)
6. In `createCharacter()`, store as `characterSheet.spells`

### 1.6 Feat Selection

**Problem**: No feat selection at all.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx` — Add feat selection step
- `client/src/components/CharacterCreatorWizard.css` — Add feat styles

**Implementation**:
1. Add `'feats'` to `WizardStep` and `STEPS`, positioned after `'spells'`
2. Make the step **conditional** — only show if:
   - Variant Human race selected (gets 1 free feat at level 1), OR
   - Character level >= 4 (ASI/feat at levels 4, 8, 12, 16, 19), OR
   - Custom Lineage / other feat-granting options
3. Feat picker UI:
   - Searchable list of feats from compendium
   - Show prerequisites (e.g., "Prerequisite: Strength 13+")
   - Gray out feats whose prerequisites aren't met
   - Allow selecting 1 feat (or more if multiple ASI levels)
4. Store in `characterData.selectedFeats: any[]`
5. In `createCharacter()`, merge feat features into `characterSheet.features`

## Phase 2: Important Enhancements

### 2.1 Armor Class Calculation

**Problem**: AC is hardcoded to `10 + Dex mod`, ignoring armor.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx` — Calculate AC from armor

**Implementation**:
1. After equipment step, check if character has armor in inventory
2. For each armor item, read `system.ac` or `system.armor` value
3. Apply armor AC rules:
   - No armor: `10 + Dex mod`
   - Light armor: `base + Dex mod` (full)
   - Medium armor: `base + Dex mod` (max 2)
   - Heavy armor: `base` (no Dex)
   - Shield: `+2` to total AC
4. Use calculated AC for `characterSheet.armorClass`

### 2.2 Alignment Selection

**Problem**: Alignment is always `undefined`.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx` — Add alignment picker

**Implementation**:
1. Add alignment dropdown in the Name step or a small dedicated section
2. Options: LG, LN, LE, NG, NN, NE, CG, CN, CE, Unaligned
3. Store in `characterData.alignment`
4. Pass through to `characterSheet.alignment`

### 2.3 Darkvision and Racial Senses

**Problem**: Race darkvision is collected but not stored/applied.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx`
- `client/src/components/CharacterSheetPanel.tsx`

**Implementation**:
1. Parse `raceSystem.darkvision` (number in feet) and `raceSystem.senses`
2. Store in `templateInstance.traits.senses` and `characterSheet.notes` (as JSON)
3. Display in CharacterSheetPanel combat/stats section

### 2.4 Language Selection

**Problem**: Race and background languages are not collected.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx`

**Implementation**:
1. Parse `raceSystem.languages` and `backgroundSystem.languages`
2. Auto-grant languages from race and background
3. If race grants "choose 1 extra language", present a picker
4. Store in `characterSheet.notes` as JSON (no dedicated column exists — could add one later)

### 2.5 Personality Traits, Ideals, Bonds, Flaws

**Problem**: Only `ideals` is set from background feature. Full personality section is empty.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx`
- `client/src/components/CharacterCreatorWizard.css`

**Implementation**:
1. Add a "Personality" section in the Background step or as a separate step
2. Parse background entries for personality trait tables/options
3. Provide text areas for each: Traits, Ideals, Bonds, Flaws
4. Store in `characterSheet.traits`, `ideals`, `bonds`, `flaws`

### 2.6 Backstory and Appearance

**Problem**: No text fields for backstory, age, height, weight, eyes, skin, hair.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx`

**Implementation**:
1. Add text fields in the Name step (or a "Details" sub-step):
   - Age, Height, Weight (text inputs)
   - Eyes, Skin, Hair (text inputs)
   - Backstory (textarea)
2. Pass through to `characterSheet` fields (all already exist in schema)

## Phase 3: Advanced Features

### 3.1 Point Buy Calculator

**Problem**: Only standard array and manual adjustment. No point buy.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx`

**Implementation**:
1. Add toggle on Abilities step: "Standard Array" | "Point Buy" | "Manual"
2. Point Buy mode:
   - Start all abilities at 8
   - 27 points to spend
   - Cost table: 8→9 (1pt), 9→10 (1pt), 10→11 (1pt), 11→12 (1pt), 12→13 (1pt), 13→14 (2pt), 14→15 (2pt)
   - Max 15 before racial bonuses
   - Show remaining points
3. Racial bonuses applied after point buy

### 3.2 Multi-classing Support

**Problem**: No support for multi-classing.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx`
- `server/src/routes/data.ts` — Character sheet schema
- `server/prisma/schema.prisma` — Add classLevels JSON field

**Implementation**:
1. Add ability to add additional classes in the Class step
2. Track levels per class: `{ class: "Fighter", levels: 3 }, { class: "Rogue", levels: 2 }`
3. Total character level = sum of all class levels
4. Collect features, proficiencies, spellcasting from each class
5. Store as `classData: { primary: {...}, multiclass: [...] }`
6. **Note**: This is a larger feature — recommend a separate PR

### 3.3 Spell Slot Tracking

**Problem**: `classSystem.spellSlots` referenced but never populated.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx`
- `client/src/components/CharacterSheetPanel.tsx`

**Implementation**:
1. Build spell slot table based on class and level
2. Use 5eTools `classSystem.spellSlots` or hardcode the standard table
3. Store in `templateInstance.resources.spellSlots`
4. Display in CharacterSheetPanel spells tab

### 3.4 Equipment: Starting Gold Option

**Problem**: No option to take starting gold instead of class equipment.

**Files to modify**:
- `client/src/components/CharacterCreatorPanel.tsx`

**Implementation**:
1. In Equipment step, add toggle: "Starting Equipment" | "Starting Gold"
2. If gold: parse `classSystem.startingEquipment.gold` or `classSystem.wealth`
3. Roll or use average gold amount
4. Skip equipment auto-selection, let player buy from item browser

## Phase 4: Polish & Edge Cases

### 4.1 Race Step: Fetch Full Race Data

Currently the race step stores the list item, but doesn't fetch the full compendium entry. Add the same `fetchFullCompendiumEntry` pattern used for class and background.

### 4.2 Equipment: Weapon Proficiency Validation

Warn (don't block) if a selected weapon isn't in the character's proficiency list.

### 4.3 Character Sheet: Show Subclass

Update the CharacterSheetPanel header to show "Level X ClassName (SubclassName)" format.

### 4.4 Character Sheet: Display Racial Traits

Parse and display race traits (darkvision, speed, ability bonuses) in a dedicated section.

### 4.5 Review Step: Comprehensive Summary

Expand the review step to show:
- Subclass selection
- Skill proficiencies (class + background)
- Known spells
- Selected feats
- Racial bonuses applied
- Final AC calculation breakdown

## Testing Strategy

For each feature:
1. **Unit tests**: Test parsing functions (ability bonuses, skill choices, spell counts)
2. **Integration tests**: Create a character end-to-end with the wizard, verify all fields populated
3. **Visual tests**: Verify the CharacterSheetPanel displays all new data correctly
4. **Edge cases**: 
   - Class with no subclasses (e.g., at level 1-2)
   - Non-spellcasting class (no spell step)
   - Race with no ability bonuses
   - Variant Human feat selection
   - Level 20 character with multiple ASI feats

## Key Code Patterns to Follow

### Fetching Full Compendium Entries
The wizard already uses this pattern for class and background selection:
```typescript
const fullClass = await fetchFullCompendiumEntry(cls.id, cls);
```
Apply the same pattern to **race** and **subclass** selection.

### Feature Collection Pipeline
The existing `collectEntityFeatures(entity, sourceLabel)` function already handles:
- `entity.system.classFeatures` / `entity.system.subclassFeatures`
- `entity.system.subclass[].classFeature` / `entity.system.subclass[].features`
- `entity.raw.classFeature` / `entity.raw.subclassFeature`

For subclass: pass the **selected subclass object** directly to `collectEntityFeatures(selectedSubclass, 'subclass')`.

### Equipment Choice System
The existing `parseClassEquipment()` / `parseBackgroundEquipment()` pattern handles:
- `startingEquipment.default[]` — granted items
- `startingEquipmentOptions[]` — choice groups
- `startingEquipmentDefault[]` — a/b loadout branches

Apply the same pattern for **skill choices** from `startingProficiencies.skills`.
